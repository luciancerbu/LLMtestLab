### Export Script (run via `execute_blender_code`):
Use absolute paths on the host machine. Example pattern — adapt `EXPORT_ROOT` to your project:

```python
import bpy
import os

EXPORT_ROOT = "/absolute/path/to/exports/marble_run"  # must exist or be created
os.makedirs(EXPORT_ROOT, exist_ok=True)

def export_selected_glb(obj_name: str, filename: str):
    obj = bpy.data.objects.get(obj_name)
    if obj is None:
        raise RuntimeError(f"Missing object: {obj_name}")
    bpy.ops.object.select_all(action='DESELECT')
    obj.select_set(True)
    bpy.context.view_layer.objects.active = obj
    filepath = os.path.join(EXPORT_ROOT, filename)
    bpy.ops.export_scene.gltf(
        filepath=filepath,
        export_format='GLB',
        use_selection=True,
        export_apply=True,
        export_materials='EXPORT',
    )
    return filepath

export_selected_glb("MarbleBall", "marble_ball.glb")
export_selected_glb("FinishGate", "finish_gate.glb")
```

After export, verify both files exist and report their byte sizes.

### Critical Implementation Rules (coding traps):
- **Unapplied scale** is the #1 Godot import failure — always apply transforms before export.
- **Wrong origin on FinishGate** causes it to float or sink — base must be at y = 0.
- **Double-sided emissive** on thin trim may disappear at grazing angles — give emissive geometry slight thickness (≥ 0.02 units).
- **Too many triangles** on the marble defeats the low-poly look — keep ≤ 80 faces.
- **Exporting the whole scene** instead of selected roots may include junk — always `use_selection=True` per asset (see Export Script).
- **Guessing `bpy` operators** causes silent failures — use `get_python_api_docs` when uncertain.
